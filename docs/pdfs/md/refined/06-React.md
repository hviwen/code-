# 状态与数据流

## React render 是状态快照

每次 render 读取该次渲染固定的 props/state，事件闭包也捕获该快照。setter 排队触发后续 render，不会修改当前运行函数里的变量。

> 坑：调用 setState 后当前行立刻读到新值。

## React 拖动状态如何避免每个 move 都重渲染

影响每帧但不需参与 render 的 latest pointer、起点、rAF id 放 ref；每个 frame 最多提交一次视觉更新，可直接更新受控 CSS 变量/transform或批量 state…

> 坑：ref 变化会自动渲染；每个 move 同步读 layout 再写 style。

## React 组件测试如何证明迟到回包无效

为 A/B 注入可手动 resolve 的 Promise；先触发 A，再触发 B，先完成 B 并断言 B 内容，再完成 A 并断言 UI 仍是 B。通过 role/name 查询与用户操作观察结果，同时断言旧请求被取消是辅助证据，最终状态门禁才是核心。

> 坑：只测 AbortController 被调用，或用 test id 绑定 DOM 结构。

## Snapshot hotfix 变基后如何证明补丁语义未漂移

先把失败时序固化成最小测试；修复与无关格式化分提交；用 git range-diff 比较 rebase 前后提交序列，用目标 release 的 focused test/build/真实环境复现验证，再 cherry-pick 或合并。

> 坑：只看“tests passed”不保存失败 fixture；把 patch-package 当长期事实源…

## ref 与 reactive 的选择规则是什么？

原始值、可整体替换的值、跨函数传递的单一状态优先 ref；对象集合可用 reactive，但重赋值会断开原变量引用。解构 reactive 属性会丢失响应式连接，需 toRefs/toRef。

> 坑：为了少写 .value 一律 reactive。

## React startTransition 解决什么问题？

它把状态更新标为非紧急，让输入等紧急更新优先；适合筛选、图表、导航中的可中断重渲染。受控输入值通常保持紧急。

# RSC 与服务端边界

## React form Action 与原生 requestSubmit 怎样协作

requestSubmit 模拟提交按钮，携带 submitter 的 name/value 和 form overrides，执行约束验证并触发 submit；submit() 直接进入提交算法，不触发同等验证/事件。

> 坑：button 默认类型总是 button；disabled UI 等于服务端拒绝；客户端通过即可信。

## React 的 'use client' 真正划定什么边界？

它置于文件顶部，标记该模块及其传递依赖为客户端模块；从 Server Component 导入时形成 server/client 边界。把交互叶子下沉，避免把大布局、数据层和无交互依赖意外送到浏览器。

> 坑：在每个交互组件都加指令，或把数据库客户端经 client 边界导入。

## Server Component、SSR 与 Server Function 的关系是什么？

RSC 在独立服务器环境中预渲染，结果可与 Client Component 引用一起传给浏览器；SSR 是生成初始 HTML 的渲染策略，可与 RSC 配合；'use server' 标记的是可被客户端发起网络调用的 Server Function…

> 坑：用 Server Function 承担常规读请求或把它当安全边界。

## 'use client' 实际划分了什么？

它标记一个模块及其传递依赖为客户端代码；从服务端模块导入该模块时形成 RSC 边界。不是给每个交互组件都随手加的标签。把状态、事件、浏览器 API 收敛到叶子 Client Component，数据读取和静态展示尽量留在服务端以减小发送和执行的 JS。

> 坑：“没有指令就一定只在服务器运行”；组件使用位置和依赖图共同决定运行环境。

## useOptimistic 如何处理失败、乱序与重复提交

乐观层记录 clientMutationId、目标动作和 pending；服务端以幂等键/版本校验落权威结果；成功用服务端实体收敛，失败回退并可重试，迟到响应按版本忽略。

> 坑：catch 后静默回退；数组索引当 mutation ID。

## useOptimistic 如何处理服务端版本冲突与失败回滚

以服务器返回的 entity/version 为基线；Action 内派发带 operationId 的 optimistic action；服务端校验主体/对象/version。

> 坑：保存一个“旧布尔值”失败时直接恢复；忽略其他协作者已产生的新版本。

## useSyncExternalStore 的 subscribe 与 getSnapshot 契约是什么

subscribe 注册 change callback 并返回 unsubscribe；getSnapshot 只返回 render 所需的不可变快照，未变化时保持 Object.is 相等，变化时换引用。

> 坑：每次构造新对象、组件内新建 subscribe、在 getSnapshot 中写状态或发请求。

## useSyncExternalStore 的 subscribe 与 getSnapshot 契约是什么｜机制与边界

完成卡应由服务端阶段/槽位终态驱动并结合角色权限。

> 坑：看到最后一步文案就算完成。

## 跨 RSC 边界传参有哪些限制？

将其视为网络边界：传递 JSON 风格 DTO、允许的内建可序列化值或 Server Function；不要传普通回调、类实例、带原型的 ORM 对象、DOM/Event、未注册 Symbol。

> 坑：认为 'use client' 只影响 hooks，不影响 props 与依赖。
