# 类型基础与收窄

## API 响应为什么先接成 unknown

类型声明只约束本地编译；网络值可能因版本、代理、权限或异常格式偏离。边界把 JSON 视为 unknown，校验 discriminant、必填字段、数组元素和约束，再返回领域类型；失败映射为可观测的 contract error。

> 坑：as ReviewDetail、泛型 fetch<ReviewDetail> 能验证响应。

## TypeScript 如何让 Map.get() 的 undefined 边界可见？

get 返回 V | undefined，即使 has 后也应在同一控制流中收窄，或封装一个遇到缺失即抛出领域错误的 requireValue。

## TypeScript 类型在运行时会被擦除

interface、type annotation 和大多数类型操作只服务编译期，生成 JavaScript 后不检查网络数据。

> 坑：写了 response.json() as Review 就完成了数据校验。

## satisfies 与类型注解/断言分别解决什么问题？

类型注解把表达式按目标类型检查且可能扩大推断；satisfies 检查表达式满足目标约束，同时尽可能保留对象自身的窄类型；断言会要求编译器相信你，不能验证。配置表适合 satisfies Record<Key, Value>。

> 坑：以为 satisfies 会把值转换为目标类型，或以为能拒绝所有动态额外字段。

## unknown 、 any 与类型断言如何在 API 边界分工？

外部 JSON、catch 值和跨进程数据先当 unknown；用运行时 schema/守卫验证并转为领域模型。any 会关闭检查，只应在隔离的兼容层短暂使用；as 是开发者声明，不会检查或转换值，不能替代验证。

> 坑：“接口标了 User，响应就是 User”；“catch (e) 可直接读 e.message”。

## unknown 与 any 的核心差异？

机制/边界；unknown 强制使用前缩窄，any 关闭类型检查并可向外传播；信任边界优先 unknown。 取舍：解析 JSON 后仍需 schema/guard 运行时验证。

> 坑：unknown 比 any 只是写法不同。

## unknown 是安全顶层类型

任何值可赋给 unknown，但使用前必须缩窄；any 会绕过检查。

> 坑：把 unknown 立即 as 成目标类型。

## unknown 要求先证明再使用

unknown 可接收任意值，但在 narrowing 前不能随意访问；any 会关闭多数检查。用 typeof、Array.isArray、in、用户定义 type guard 或 schema parser 将值收窄。

> 坑：unknown 与 any 只是写法不同，或一次 as 就等价于检查。

## 判别联合如何避免非法 UI 状态？

机制/边界；把 loading/success/error 等建成互斥分支，每支只含合法字段；switch 穷举避免 loading 与 data 同时存在。 取舍：大型状态机可考虑 reducer，但不必为简单流程引库。

> 坑：多个可选字段就等价。

## 平台门禁怎样避免散落判断？

机制与工程边界；用类型化配置和能力表把 platformId 映射为 feature flags，组件消费能力而非硬编码平台名。 取舍：能力表需有默认拒绝与观测。

## 条件类型何时分发，为什么 T extends U 会改变结果？

当条件左侧是裸类型参数 T 时，联合类型会逐成员分发：T extends U ? X : Y。包成元组 [T] extends [U] 后测试的是整个联合是否可赋值给 U，不再分发。先写输入/输出类型测试，再决定是否需要这种能力。

> 坑：把 extends 一律解释为继承；用条件类型模拟精确对象类型。

> 坑：视觉干净优先于可发现性。

## 如何用判别联合建模 Zero 资源？

机制与工程边界；以 kind: zero_prd sub_prd 区分，并让各分支拥有最小必要字段；switch 用 never 穷举。 取舍：来自网络的数据仍需运行时校验。

## 组件 API 如何避免“布尔参数爆炸”？

先识别变体是否仍共享语义与交互。少量互斥变体用受限 union（如 variant: 'primary' | 'danger'）；复杂区域用 slots/children 或组合组件；跨领域职责拆为更小组件。为受控/非受控模式定义单一数据源、默认值与回调语义。

## satisfies 能做什么、不能做什么

> 坑：把 satisfies 当 schema validator，或认为它等价于类型断言。
