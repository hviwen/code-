## AbortController 能解决哪些问题，不能解决哪些？

**考察意图**

取消传播与可靠写入。

**核心答案**

signal 可被 `fetch`、流和自定义 async API 监听，停止未完成的协作工作；适合卸载、换词、超时和用户取消。它不保证请求未发出、服务端未执行或数据库写入撤销；写路径仍要幂等、可查询。

**追问**

父 signal、deadline signal 和子请求如何组合并保留原因？

**边界/误区**

每次逻辑请求用独立 controller；不要吞掉所有错误伪装为取消；“abort 等于事务回滚”是错的。

**来源/审校**

Node.js Best Practices、MDN；**已修订**，补齐未知写入结果。

## Anchor Positioning 是布局增强不是语义关系

**核心答案**

CSS Anchor Positioning 让绝对定位元素相对命名 anchor 计算位置，并可定义 fallback。

anchor 名称、`position-anchor`、`anchor()`/`position-area` 和 `position-try-fallbacks` 共同参与布局。

**边界与取舍**

它不自动提供 tooltip/menu 的角色、焦点、关闭和无障碍描述；不支持时基本交互仍须成立。

**常见误区**

用了 anchor positioning 就不再需要 Popover/Dialog 语义或 JS 状态。

## Dialog 与 Popover 如何按模态性选择

**问题**

数据看板筛选浮层、逾期详情和删除确认分别选什么？

**考察意图**

HTML top layer、焦点、dismiss 与交互阻断。

**核心答案**

轻量筛选/提示通常用非模态 Popover；必须回应的删除确认用 `dialog.showModal()`；逾期详情按是否允许继续操作决定。语义先于视觉，需验证触发器关系、Escape/取消、焦点返回和不支持能力的降级。

**边界与取舍**

`popover=auto/manual/hint` 关闭规则不同；`closedby`/命令属性按目标浏览器核验。自定义 Drawer 若有阻断语义仍需完整 focus/inert 管理。

**常见误区**

Popover 有 backdrop 就是 modal，或 `dialog.show()` 等价于 showModal。

**追问**

## pending UI 如何兼顾 HTML 语义与动效

**问题**

提交按钮 pending 时应如何处理 disabled、aria-busy、状态文本与动画？

**考察意图**

HTML/CSS、可访问性和重复提交。

**核心答案**

真实不可重复提交时用原生 `disabled`；区域加载可用 `aria-busy`，关键结果用合适 live region；保留稳定尺寸避免布局跳动，并尊重 `prefers-reduced-motion`。

**边界与取舍**

disabled 控件不触发点击且通常不获焦；需要保留解释/焦点时可用受控 guard + `aria-disabled`，但必须代码阻止动作。

**常见误区**

只降低 opacity，或给所有更新都用 assertive live region。

**追问**

如何让回滚消息对键盘和读屏用户可感知？

**快答**

按真实交互选 disabled/aria-disabled，区域用 aria-busy，状态可感知且尊重 reduced motion。

## script async、defer、module 加载语义

**问题**

经典脚本的默认、async、defer 与 type=module 在下载、执行顺序和 DOMContentLoaded 上有什么差异？

**核心答案**

默认外部经典脚本遇到时抓取并执行，阻塞 HTML 解析。async 并行下载、下载完尽快执行，多个脚本不保证文档顺序，适合相互独立脚本。defer 并行下载，解析完成后按文档顺序执行，并延后 DOMContentLoaded。模块脚本默认 defer；其依赖图和跨域规则与经典脚本不同。动态插入脚本另有语义，不能机械套用。

**边界与取舍**

- “async/defer 完全不阻塞页面”不严谨：执行阶段仍占用主线程。
- 内联经典脚本使用 defer 无效。
- defer 不等于等待图片等所有资源加载完成。

**追问**

第三方统计脚本为何常用 async？模块脚本为什么需要正确 MIME 与 CORS？

## 如何为 SPA 路由切换设计焦点与标题？

**核心答案**

路由完成后更新 `document.title`，把焦点移到页面主标题或主内容容器（通常 `tabindex="-1"`），并提供跳到主内容的 skip link。这样键盘和读屏用户不会从旧导航位置“迷路”。

**边界与取舍**

不要在每次局部状态更新抢焦点；错误、成功提示只在必要时用 live region，并避免重复/过度播报。

**追问**

React/Vue 中何时移动焦点？——在 DOM 已提交且切换已确认后，通过 ref 处理；要避免 Strict Mode/重复渲染造成抖动。

## 何时用语义 HTML，而不是用 div 加 ARIA？

**考察意图**

语义、可访问性与渐进增强。

**核心答案**

原生元素已表达意图时优先使用它：导航用 `nav`、主内容用 `main`、可触发动作用 `button`、跳转用 `a[href]`、表单控件用对应 input。它们自带键盘行为、焦点、可访问名称与浏览器默认语义；ARIA 用来补足不能用原生元素的复合组件，而非重造按钮。

**边界与取舍**

自定义组件可封装原生元素；若必须用非原生元素，需补齐 role、tabindex、键盘、disabled 语义和测试，成本更高。

**常见误区**

`role="button"` 不会自动获得 Space/Enter 行为；点击 `div` 不是可访问按钮。

**追问**

弹窗的焦点进入、循环和返回如何设计？

## form.submit() 、点击 submit 按钮和 requestSubmit() 有何区别？

**考察意图**

浏览器提交路径与事件。

**核心答案**

**边界与取舍**

提交监听应在 `submit` 上统一处理并使用 `event.submitter` 识别操作，而不是只监听某个按钮 click；要防御无 submitter 的程序化路径。

**常见误区**

`preventDefault()` 会让表单自动变有效；所有提交 API 行为相同。

## 为什么“能点击的 div”不是按钮的等价替代？

**考察意图**

是否理解语义、键盘、焦点和辅助技术是同一份交互契约。

**常见误区**

`tabindex="0"` 就“无障碍了”。

## 前端如何设计“提交后才显示错误”的可访问校验体验？

**考察意图**

**核心答案**

## 一个真正的模态对话框需要满足哪些焦点条件？

**核心答案**

打开时焦点进入对话框内合适的元素；Tab/Shift+Tab 不离开其可聚焦范围；Escape 有明确关闭策略；关闭后返回触发者，除非触发者消失或后续工作流有更合理去处；背景对所有用户均不可交互。对话框要有可访问名称和可见关闭操作。

**边界与取舍**

长内容不应一打开就把焦点塞到危险操作；不可逆动作优先聚焦最不具破坏性的选择。原生 `<dialog>` 能减少基础工作，但仍需测试焦点、嵌套、滚动与各浏览器行为。

**常见误区**

## 何时该用 ARIA，何时不该用？

**核心答案**

ARIA 用来补足没有等价原生语义的复杂 widget 或动态状态；能用原生 HTML 就用原生 HTML。添加 role/state/property 后，开发者必须实现与其匹配的键盘行为、状态同步和焦点管理。

**边界与取舍**

`aria-hidden="true"` 的元素及其后代不应承载可聚焦交互；ARIA 不改变视觉和业务权限。

**常见误区**

给所有元素都加 role，或把 `aria-label` 当成修复语义结构的万能贴纸。

## 自动化 a11y 扫描能证明页面合规吗？

**核心答案**

**边界与取舍**

扫描零问题只是门槛通过，不是质量结论。

## 如何落实减少动态效果？

**考察意图**

可访问性不是关闭一切反馈。

**核心答案**

用 `@media (prefers-reduced-motion: reduce)` 替换或缩短非必要缩放、平移、视差和自动播放；保留焦点、完成/错误等必要状态的低运动替代，并让用户可控。

## 如何让列表、菜单、Tab 组件的键盘导航可维护？

**核心答案**

**边界与取舍**

## 颜色对比、焦点样式与 prefers-reduced-motion 如何协作？

**核心答案**

**常见误区**

用 `outline: none` 消灭焦点环，或把“减少动效”理解为关闭所有过渡。

## 触摸目标和点击延迟如何设计与验证？

**考察意图**

交互可用性与性能证据。

**核心答案**

目标尺寸、间距、可见 pressed/focus 状态应来自设计系统并在真机可达；避免在滚动容器中无必要地阻塞默认触摸行为。用真实设备、不同手势和 INP/错误点击指标验证，而非只看模拟器。

**边界与取舍**

较大热区不能遮挡相邻语义控件；手势冲突先调整交互，再谨慎使用 `touch-action`。

**常见误区**

把所有性能问题归咎于“300ms 点击延迟”。

**追问**

如何支持鼠标、触摸和键盘？——使用语义 `button`，让浏览器提供多输入路径，再按需增强 Pointer Events。

## Transition 调整更新优先级，不保证请求顺序

**核心答案**

Transition 把可中断的非紧急 render 与输入等紧急更新分开。

紧急更新可打断并重启 Transition；`useTransition` 额外提供 pending 状态。

**边界与取舍**

不能用 Transition 控制文本输入；自建 async Action 的多次请求仍可能乱序，需 version、abort 或队列。

**常见误区**

`startTransition` 会延迟执行回调，或包住 async 请求就自动“最后一次获胜”。

## 自动加载抑制

**核心答案**

深链进入时需抑制会覆盖目标的默认自动加载。

**边界与取舍**

抑制只在初始化窗口生效。

**常见误区**

用全局布尔值永久关闭加载。
