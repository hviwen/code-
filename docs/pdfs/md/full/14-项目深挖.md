## PRD TRD 评审接口的鉴权与错误契约

**问题**

如何把评审接口从“能联调”升级为安全、可观测的生产契约？

**核心答案**

主体/对象/动作 → endpoint/service/model 边界 → request/response runtime schema → BOLA/BFLA → problem details → 幂等/版本 → 审计/指标 → 双身份/异常测试 → 灰度回滚。

**边界与取舍**

共享 error envelope/鉴权 middleware 降低遗漏；PRD/TRD 领域字段仍分开，避免过度统一成大而松的 DTO。

**追问**

读取权限与“通过评审”动作权限怎样独立建模？

**风险**

信任 client role/userId、批量部分越权、错误泄露、重复提交、迟到回包、schema coercion 和日志含评审正文。

**落地改进**

服务端逐对象授权；前端 `unknown` parser；403/404 策略；correlation ID；fixture/双身份/乱序测试；按接口版本灰度。

## PRD/TRD 空正文保护的数据完整性闭环

**问题**

如何让 PRD、TRD、AI refresh 与自动保存共用一条“空正文不覆盖”防线？

**核心答案**

威胁模型（默认模板/空接口/空 SSE/unknown node）→共享领域谓词→后端内容门禁→editor revision/权限/ID→零 save fixture→日志与拒绝指标→灰度→数据恢复。

**追问**

用户主动清空整篇正文时怎样与“空响应保护”区分？

**模块边界**

`document-content` 只判断业务正文；sanitize/schema migration 处理结构合法性；编辑器负责 dirty/revision；API/后端负责权限、版本与幂等。

**状态/数据**

显式区分 loading、backend-valid、backend-empty-confirmed、dirty、saving、conflict；已有正文只由有效、更新版本替换。

**异常/性能**

递归扫描 O(n)，只在加载、刷新和保存边界执行，避免每次渲染深扫；解析失败保留现状并记录脱敏错误。

**测试/发布**

围绕 `68a8ce6b` 的 null、空 JSON/HTML、文本、图片、业务卡、TRD 边界节点做断言；CI 运行共享脚本，灰度看零写、误拒绝、冲突和恢复指标。

**风险/改进**

未知 node 被当有效可能放过垃圾，被当空可能误杀历史正文；下一步为 schema version 建允许表与隔离迁移，不添加猜测性框架。

## 实时协作编辑器建设深挖

**核心答案**

1. 维护客户端版本/能力矩阵；服务端先兼容旧新 schema，新增字段可选、未知事件可安全处理。

**风险与边界**

## Vue 性能治理与可靠性发布

**问题**

一组 BFF 集成测试在 CI 每周失败数次、本地难复现；你怎样治理并安全交付？

**核心答案**

为每次失败保留 commit、运行器、并发度、seed、耗时、日志和 trace；按测试断言/资源泄漏/网络依赖/端口文件竞争/基础设施分类；将最小复现放入隔离 suite，控制时钟、随机源、网络、临时目录和端口；关闭未释放 handle，避免跨用例全局状态；用重试只做短期止血并建 issue、失效日期和恢复门槛。

## pnpm 7 到 10 迁移与发布隔离

**问题**

你如何把一次大版本包管理器迁移拆成可验证、可回滚的工程变更？

本地 /Users/ext.panhuiwen1/hankins/uniops-ui 将 packageManager 从 pnpm 7.33.7 改到 10.25.0，lockfile 5.4→9.0，产生约 1.36 万行 diff；另一个 checkout 的构建调整也修改了 927 行 lockfile。

**核心答案**

1. 需求：先确认是工具版本治理，不顺带升级依赖。
2. 边界：manifest、workspace 配置、lockfile、patch、CI 镜像和缓存是一条链。
3. 验证：干净安装、frozen lockfile、解析版本差异、类型检查、测试、构建、核心页面。
4. 发布：独立提交和灰度 CI；失败时回滚 packageManager 与 lockfile 整组文件。
5. 可观测性：记录安装耗时、缓存命中、依赖与 patch 漂移、构建产物差异。

**追问**

如何证明“依赖没升级”？如何设计失败回滚而不留下旧 node_modules 污染？

**关键取舍与风险**

- 原地迁移最短，但必须隔离依赖升级与业务代码。
- 缓存提速不能牺牲可信边界；不可信任务不能写入被可信任务复用的依赖缓存。
- patch hash 改变、peer 组合变化和 install script 是高风险点。

**落地改进**

统一 packageManager；CI 读取同一版本；frozen 安装；保存解析版本对比；迁移 PR 禁止混入格式化。

## 可访问动效的灰度发布与回滚

**问题**

如何给抽屉/列表→详情加入动效，同时控制兼容、性能和发布风险？

**核心答案**

状态更新不变量 → CSS/native 优先 → reduced motion/focus → API 能力探测 → 竞态/错误 → 浏览器矩阵 → 测试/CI → feature flag/版本指标/回滚。

**边界与取舍**

短 CSS transition 最简单；View Transition 适合跨状态连续感，但兼容和捕获成本需验证；复杂动画不应阻塞业务更新。

**追问**

如何区分“更顺滑”和“只是更慢但有动画”？

**风险**

重复导航、动画结束未触发、截图层内存、旧浏览器、读屏顺序、样式回归和指标归因错误。

**落地改进**

无动画路径先通过；加入 reduce 分支、焦点测试、视觉/trace 基线；动效单独开关，提交拆分使回滚不撤销业务功能。

> 难度 高级 · 审校 已修订 · 首次 2026-08-24 · 主体系

局部组件状态更省代码，但跨入口一致性优先时应提升到共享命令或 URL/服务端契约。

**追问**

**风险**
