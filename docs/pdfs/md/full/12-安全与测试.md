## CSP 是纵深防御

**核心答案**

通过允许列表/nonce/hash 限制脚本等资源，减少 XSS 影响。

**边界与取舍**

CSP 不替代输出编码、Trusted Types 或依赖治理。

**常见误区**

只在 meta 随便加 default-src *。

## PRD 门禁是状态解析，不是按钮判断

**核心答案**

把文档存在性、权限、平台、处理状态归一成可穷举状态；UI 只消费状态。

**边界与取舍**

门禁不会替代服务端鉴权。

**常见误区**

只在按钮组件里散落 if。

## textContent 、 innerHTML 与框架原始 HTML 注入如何选？

**核心答案**

展示不可信文本时使用 `textContent`（或框架默认文本插值），让浏览器创建文本节点；只在业务确需富文本时允许受控 HTML，先采用维护中的 allowlist 消毒器，按输出上下文限制标签/属性/URL 协议，并在服务端/客户端的渲染边界一致处理。不要把消毒后的字符串再次拼接到 HTML、JS 或 URL 上下文。

**边界与取舍**

消毒器配置、SVG/MathML、链接跳转和服务端渲染都要独立测试；授权错误不是 XSS 清洗器能解决的。

**常见误区**

“React/Vue 默认转义，所以 `dangerouslySetInnerHTML`/`v-html` 也安全”。

# 测试分层与策略

> **类型** 安全与测试 · **难度** 基础（基础 1） · **条目** 9
>
> **时效** 内容采集于 2026-06 ~ 2026-09；含版本或性能指标相关结论，请按当前版本复核。

## API 版本

**核心答案**

版本升级应明确路径、schema、兼容窗口和回滚策略。

**边界与取舍**

版本号不能替代契约测试。

**常见误区**

改成 /v2 即完成迁移。

## 如何为高风险前端流程设计测试分层？

**考察意图**

能否从风险而不是工具偏好出发。

**核心答案**

先列关键资产、失败模式和可观察结果，例如支付金额、重复扣款、认证过期、回调乱序。纯函数/校验规则用快速单测；组件与请求状态用集成测试；支付、登录等少量关键旅程用真实浏览器 E2E；服务边界用合约测试。每层都写清证明什么、不能证明什么，以及失败证据。

**边界与取舍**

金字塔不是固定比例；遗留系统可先为高风险路径补集成/E2E，再逐步抽离可单测逻辑。

**常见误区**

“E2E 最真实，所以全靠 E2E”。

**追问**

如何把生产故障转为回归测试？

**来源与审校**

curated + primary；**已准入**，current。

## 单测、集成、E2E 分别要证明什么？

**核心答案**

单测证明一个受控单元在明确输入下的规则；集成测试证明多个真实协作单元（渲染、状态、请求适配器）能得到用户可见结果；E2E 证明部署后关键旅程在浏览器和真实协议条件下可完成。三者不是互相替代。

**边界与取舍**

E2E 不替代对错误分支的穷举，单测也不能证明 bundler、Cookie、焦点或浏览器权限。

**常见误区**

把“覆盖率高”当成行为已经验证。

## 如何处理 E2E 的并行、数据隔离和失败证据？

**核心答案**

为 worker 分配独立租户/账号/测试数据前缀；每例创建与清理数据，避免共享可变状态；密钥由 CI 安全注入；失败时保存 trace、截图、视频、网络与服务端关联 ID。重跑只用于判别 flaky，不能掩盖首失败。

**追问**

如何让清理失败可恢复？用 TTL、专用命名空间和后台回收。

## 怎样测试 RSC 与离线状态机？

**考察意图**

测试层次和可观测性。

**核心答案**

单测覆盖 DTO 映射、可序列化检查、队列状态转移和冲突归类；集成测覆盖 server/client 边界、鉴权与 idempotency；E2E 在真实浏览器或设备模拟首次启动、两次离线重启、网络抖动、会话过期、重复提交和升级迁移。记录 queue length、恢复耗时、重放结果、冲突率，但脱敏且不记录 payload。

**边界与取舍**

jsdom 不能代表 SW、浏览器存储配额或 RN 生命周期；关键路径需要真机/浏览器覆盖。

**常见误区**

只 mock `navigator.onLine`，不控制实际请求失败与恢复次序。

**追问**

哪些指标能证明新离线策略没有增加重复写入？

## 测试层级按失败成本和证据选择

**核心答案**

单元测纯逻辑，组件测用户可见交互，契约测边界格式，集成测真实协作，E2E 测关键业务路径。

把多数边界条件放在快速确定性测试，少量关键路径留给浏览器/真实依赖。

**边界与取舍**

E2E 不能替代 parser 的穷举反例；单元测试也不能证明路由、样式、浏览器或服务部署正确。

**常见误区**

所有行为都上 E2E，或单测通过即等于页面可用。

## 为什么测试用户可见行为而非实现细节？

**核心答案**

用户关心可访问名称、输入、反馈和可提交结果；以它们定位可在重构组件层级、state 管理或 hook 时保持测试价值。用角色/标签查找元素，断言状态和副作用；只在公共契约确实是实现级 API 时测试该 API。

**边界与取舍**

对纯 reducer、解析器或复杂状态机，直接单测接口更快更清晰。

**常见误区**

断言私有 state、class 名或 `setState` 次数。

## 评审功能应在哪些层测试

**问题**

PRD 评审从 service 到页面，如何分配单元、契约、组件和 E2E 测试？

**考察意图**

测试分层、风险优先级和证据边界。

**核心答案**

纯 parser/model/轮询状态转移做快速单元与属性测试；请求方法、路径、body、错误格式做契约测试；组件以可访问角色和用户操作验证 loading/success/error/permission；E2E 只覆盖创建→轮询→通过/驳回、双身份拒绝等高价值链路。

**边界与取舍**

真实服务 E2E 少而稳定；Mock 不能证明生产契约，浏览器 E2E 也不应穷举所有 JSON 反例。

**常见误区**

按代码文件一比一造测试，或只追覆盖率。

**追问**

一次接口字段变更应先在哪层失败？

## 如何验证实时功能已可上线？

**考察意图**

测试与发布治理。

**核心答案**

单测事件 reducer；集成测试重复、乱序、401、版本冲突；E2E 模拟双用户/弱网/后台切换；灰度开关与协议兼容矩阵；依据同步 p95、补快照率、错误率决定扩量或回滚。

**核心答案**

## CSP、Cookie 属性和 CSRF 分别解决什么？

**核心答案**

输出编码/消毒先防注入；CSP 限制允许的脚本、样式等来源并可报告违规，降低注入利用面；`HttpOnly` 减少 JS 读取 Cookie，`Secure` 只走 HTTPS，`SameSite` 限制跨站发送；CSRF 对 cookie 身份认证的跨站伪造补充用同源 token、Origin/Referer 校验等服务端验证。它们分层互补。

**边界与取舍**

SameSite 不是所有跨站嵌入/登录流的替代方案；token 存储也有 XSS 权衡。

## 前端权限控制为何不是安全边界

**问题**

评审按钮只有创建人可见，是否已阻止他人调用通过/驳回接口？

**考察意图**

认证、BOLA/BFLA 与前后端职责。

**核心答案**

没有。前端可见性只改善 UX；攻击者能直接构造请求。服务端必须基于已认证主体，对目标 review/resource 和 action 做对象级/功能级授权，避免信任 client userId/role；用至少两个身份做交叉访问测试并审计拒绝事件。

**边界与取舍**

前端仍应隐藏/禁用不可用动作，减少误操作；但不能从 403 推断资源一定存在，也不能记录完整敏感对象。

**常见误区**

UUID 不可猜、按钮隐藏或 TypeScript role union 能阻止越权。

**追问**

批量接口怎样防止部分对象越权？

## 双身份测试如何证明对象级授权

**问题**

评审详情和通过接口怎样做 BOLA 回归测试？

**考察意图**

安全测试、身份/对象矩阵和证据强度。

**核心答案**

A 创建对象 XA，B 创建 XB；验证 A→XA、B→XB 成功，A→XB、B→XA 在详情和动作路径被服务端拒绝，再覆盖跨租户、批量和不存在对象。断言无敏感 body、无副作用、审计事件正确；token 从受控测试环境注入且报告脱敏。

**边界与取舍**

**常见误区**

仅换数字 ID、仅测按钮隐藏或复用管理员 token。

**追问**

列表过滤正确能否推出详情安全？

## 授权测试需要至少两个真实身份

**核心答案**

**常见误区**
