## pagehide 与 sendBeacon 能否保证离场保存

**问题**

把最终正文只放在 `pagehide` 中用 `sendBeacon` 保存，是否可靠？

**考察意图**

页面生命周期、传输限制、确认语义和恢复。

**核心答案**

不可靠。移动端可能不触发 pagehide；beacon 只支持 POST、小数据且 true 仅表示进入发送队列。主路径应持续增量保存并有服务端版本确认；`visibilitychange`/`pagehide` 只发送小型、幂等的 dirty/revision 提示或最后增量，下一次打开再对账恢复。

**边界与取舍**

需要自定义 method/header/读取响应时可考虑 `fetch(...,{keepalive:true})`，仍不可承诺完成。大正文应提前分片或常态保存。

**常见误区**

在 unload 阻塞导航；beacon 传完整富文本和敏感数据；返回 true 立即显示“已保存”。

**追问**

客户端崩溃、断网和 bfcache 恢复分别怎样验证？

## 后端返回空正文时为何不能立即初始化并保存模板

**问题**

接口短暂返回 null/空 TipTap doc，编辑器初始化默认 paragraph 并触发 onUpdate，怎样避免覆盖后端已有正文？

**考察意图**

来源门禁、加载态、默认值污染和数据丢失防护。

**核心答案**

区分 loading、backend-content-present、backend-empty-confirmed、error；只有取得可信后端正文后才允许自动保存，默认模板不产生“用户已编辑”事实。AI refresh/重试同样先验证有效正文，空响应保留现有编辑器状态。保存前再次校验 backend gate、编辑权限、ID、当前正文和 revision。

**边界与取舍**

明确的新建文档可由后端创建版本/初始正文后开放保存；不能用一次网络错误推断“空文档”。用户主动清空若是合法操作，应走显式删除/空版本契约，而不是被保护逻辑永久阻止。

**常见误区**

`content ?? defaultTemplate` 后立即 autosave；空 SSE 刷新 setContent；只在 PRD 修而漏 TRD/导入/AI 路径。

**追问**

如何测试 `content:null` 产生零 save 请求，同时图片和业务卡仍可保存？

## contenteditable 与编辑锁怎样组成一致权限边界

**问题**

只把根元素设为 `contenteditable=false`，是否足以阻止只读用户修改和提交正文？

**考察意图**

HTML 枚举属性、UI/服务端授权、编辑器命令与粘贴输入。

**核心答案**

不足。`contenteditable` 是 UI 编辑能力，不是安全边界；只读态还要禁用编辑器 commands、自动保存、AI 写入、快捷键/拖拽/粘贴入口，服务端按用户与 editSession/version 校验写权限。属性是 enumerated，不是普通 Boolean；嵌套可编辑区和 node view 需单独验证。

**边界与取舍**

只读仍可允许选择/复制/评论；可访问状态需清楚提示锁拥有者和恢复路径。RN/uni-app 不应假设同一 DOM 行为。

**常见误区**

`:disabled` 样式等于后端拒写；字符串 `contenteditable="false"` 被框架错误当 truthy；隐藏保存按钮但 API 仍可调用。

**追问**

如何用双身份浏览器测试证明非 owner 无写请求？

## 怎样定义结构化编辑器的有效正文

**问题**

`{type:'doc',content:[{type:'paragraph'}]}`、空 HTML、图片节点和业务卡片分别应如何判断是否可保存？

**考察意图**

领域谓词、递归树、trust boundary 和无文本节点。

**核心答案**

先拒绝 null、数组和无 type 对象；字符串先 trim，JSON 字符串解析后递归，HTML 用 DOMParser 读取文本并白名单检查媒体/业务节点；JSON 中 text 节点要求非空文本，容器递归 children，允许的 atom/业务节点即使无 text 仍可算正文。谓词服务于保存门禁，不等于 schema 校验或 XSS 清洗。

**边界与取舍**

未知 node 不应一律当有效正文；应按当前 schema/迁移表决定 reject、隔离或兼容。附件占位、失败卡片是否算正文由产品定义。

**常见误区**

只看 `textContent`，会误杀图片/mention/card；只看对象 truthy，会把默认空段落当正文。
