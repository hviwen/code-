## useTransition 解决什么、不解决什么

**问题**

搜索输入和大列表筛选何时使用 `useTransition`？

**考察意图**

React 并发调度与性能边界。

**核心答案**

输入值 urgent 同步更新，把可中断的大列表/路由结果更新放入 Transition；用 `isPending` 提供非阻塞反馈，并以 Profiler/用户指标证明收益。

**边界与取舍**

它不取消 fetch、不缩短计算总量、不适合受控输入状态；昂贵同步循环仍会阻塞主线程。

**常见误区**

Transition 等于 debounce 或 Web Worker。

**追问**

await 后的更新为什么有时需再次 `startTransition`？

**快答**

标记可中断的非紧急更新；不取消网络、不缩短总计算、不用于受控输入值。

## 并发回包如何只让最新意图生效

**问题**

用户快速切换 PRD→TRD 评审，两次详情请求乱序返回怎样收敛？

**考察意图**

React/异步状态、取消与竞态。

**核心答案**

每次意图生成 request key/version；新请求取消旧 AbortController，并在写状态前再次核对 key。取消只是资源优化，最终写入门禁才保证不被无法取消或已完成的旧响应覆盖；mutation 还需幂等键和服务端版本。

**边界与取舍**

缓存库可管理 dedupe/stale，但业务身份和授权变更仍需显式 key；不要吞掉真实错误当取消。

**常见误区**

effect cleanup 或 AbortController 单独即可证明无竞态。

**追问**

同一资源刷新与切换资源如何定义 key？
