## Structured clone 的类型、身份与 transfer 边界如何测试

**问题**

怎样证明对象图跨 Worker 后语义仍满足业务需要？

**考察意图**

浏览器序列化、循环/共享引用、DataCloneError 和不可逆转移。

**核心答案**

为允许类型建契约 fixture：循环能恢复、同一引用仍映射到同一 clone、Date/Map/Set 值正确；函数/Proxy 等拒绝项应得到 DataCloneError；自定义实例只断言需要的数据，不断言原型/访问器；transfer 后断言源 buffer detached、接收方拥有数据。

**边界与取舍**

clone 是同步 API，超大对象仍会阻塞；SharedArrayBuffer 还受 cross-origin isolation 等条件约束。外部输入先做 schema 校验。

**常见误区**

和 `JSON.parse(JSON.stringify())` 完全等价；clone 后 `instanceof` 必然保持；transfer 可重试。

**追问**

跨 Web、RN、uni-app 时如何建立实际 runtime capability matrix？

## 为什么不能从“POST 可缓存”直接推出工程方案？

**考察意图**

框架版本、显式配置与副作用。

**核心答案**

HTTP 方法不是唯一维度；Next 的具体缓存行为取决于运行位置、版本、显式配置、响应和部署环境。对含副作用或用户特定的 POST，默认不以缓存复用为设计基础；先读当前版本官方文档并写集成测试。

**边界与取舍**

GitHub Discussion #94888 是近期困惑信号，不替代文档或版本锁定的复现。

**常见误区**

把 tag 当作自动缓存开关，或把请求 memoization 与持久缓存混为一谈。

**追问**

怎样发布缓存迁移？——加读写指标、命中/失效日志、开关和可回退路径。

## 浏览器中一次 task 与 microtask 如何推进？

**考察意图**

是否能解释而非背顺序。

**核心答案**

同步脚本或事件处理通常作为 task 执行。当前调用栈清空后，运行微任务检查点，持续取完当时队列中的微任务；微任务还能继续入队。随后用户代理可以选择更新渲染，再取下一 task。长 task 或无限微任务会阻塞输入与绘制。

**追问**

递归 `queueMicrotask` 为什么会让页面失去响应？

**边界/误区**

“macrotask”是常用术语，不是 ECMAScript 的正式队列名；不要说每轮必渲染。

**来源/审校**

curated + primary；**已修订**，修正“所有宿主调度都等同宏任务”。

## startTransition 能解决什么，不能解决什么？

**考察意图**

React 调度与真实性能成本。

**核心答案**

它把非紧急更新标记为可中断，使输入优先反馈；适合筛选结果、路由后大块 UI 更新。它不会减少计算、网络或 DOM 数量，受控输入本身也不应放进去。先减少无效工作、虚拟化和拆分状态。

**常见误区**

用它包裹所有 `setState`，造成过期 UI 无提示。

**追问**

如何告知用户？——用 `isPending` 表达“结果更新中”，保留当前可操作内容。

**伪代码**

`setQuery(value); startTransition(() => setFilters(derive(value)));`
