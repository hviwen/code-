## AsyncLocalStorage 怎样用于请求级诊断而不变成隐式业务依赖

**核心答案**

入口验证/生成 requestId，使用 `run` 包住完整请求处理；日志/trace 层只读不可变上下文；业务函数仍显式接收影响结果的参数。并发请求、timer、Promise、event emitter 桥接写隔离测试；上下文缺失时降级而非伪造关联。

**常见误区**

ALS 对所有库、worker 和进程边界自动传播，或可替代鉴权上下文验证。

**追问**

## highWaterMark 如何选且为何不是内存上限

**问题**

把 highWaterMark 调大是否一定提高吞吐？

**考察意图**

Node 性能、缓冲模型与测量。

**核心答案**

它是启动背压的阈值；调大可能减少调度但增加驻留内存/尾延迟，调小可能增加切换。按 chunk 大小、并发、下游速度和 RSS/GC/延迟实测。

**边界与取舍**

Node/Web/objectMode 计量不同；TLS、socket、代理和应用队列都有额外缓冲。

**常见误区**

阈值就是严格内存上限。

**追问**

## 并发修复如何进入 CI、压测和可逆发布

**问题**

取消泄漏或无界并发修复怎样证明可回迁、可发布、可回滚？

**考察意图**

失败 fixture、基准公平性、Git 与发布闭环。

**核心答案**

先保存能稳定失败的慢响应/取消交错 fixture；修复保持小提交；CI 跑单测、句柄/计时器泄漏检查和目标 Node 矩阵。压测两组使用相同 controller、连接池、预热和负载，比较吞吐、尾延迟、内存与错误率。用 `range-diff` 审查回迁，灰度观察，异常用 revert 回滚。

**边界与取舍**

微基准不替代真实链路；回滚代码不一定回滚已产生的数据副作用，写操作还需幂等/补偿。

**常见误区**

只报平均 QPS；提高 timeout 掩盖竞态；直接改写共享分支历史。

**追问**

如何设计“取消后活跃句柄回到基线”的最小门禁？
